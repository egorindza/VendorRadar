# VendorRadar

VendorRadar помогает команде вести реестр корпоративных SaaS-сервисов, планировать списания, видеть простой лицензий и подтверждать отзыв доступов сотрудников. В локальном демо доступны два рабочих пространства с независимыми данными.

## Запуск на Windows

Нужны .NET 10 SDK, MS SQL Server 2016 или новее с включённой поддержкой temporal tables и современный браузер. Проверено на .NET SDK 10.0.401, SQL Server 17.0.1155.3 и Git 2.55.

```powershell
Set-Location C:\Portfolio\VendorRadar
dotnet --list-sdks
dotnet build VendorRadar.sln
dotnet test VendorRadar.sln
dotnet run --project src/VendorRadar.Web
```

Откройте [VendorRadar на localhost:5107](http://localhost:5107). Профиль запуска использует локальный экземпляр SQL Server через Shared Memory и аутентификацию Windows. При первом старте процесс с правами на создание схемы создаёт или обновляет **VendorRadar_SaasDb**, затем загружает демоданные. Если используется именованный или удалённый экземпляр, задайте подходящую строку в `ConnectionStrings__VendorRadar` и отдельную строку миграций в `ConnectionStrings__VendorRadarAdmin` при необходимости. Для удалённого SQL Server настройте TLS и проверяемый серверный сертификат.

HTMX и браузерный клиент SignalR поставляются локально в `wwwroot/lib` вместе с лицензиями. После восстановления NuGet браузеру достаточно доступа к локальному приложению.

## Демо за несколько минут

| Роль | Что открыть |
| --- | --- |
| CEO / FinOps | Обзор с MRR, ARR, сроками и расходами по отделам, финансовый PDF, редактирование контракта, история цены и финальное решение по заявке |
| IT Security Admin | Матрица доступов, шаблоны и мастер онбординга, «Чек-листы доступов» и незавершённый оффбординг Максима Соколова в Northstar Studio |
| Team Lead | Заявки своего отдела. В Northstar Studio есть заявка Miro Enterprise, совпадающая с действующим доменом |

В Northstar Studio 26 SaaS-сервисов, а в Meridian Labs ещё 6. Компании, сотрудники и их расходы демонстрационные. Проверьте изоляцию, открыв Slack в Northstar, сменив компанию через меню рабочего пространства и снова открыв сохранённый URL. Запись доступна только в Northstar. Для проверки SignalR откройте один чек-лист в двух вкладках и подтвердите задачу в первой. Во второй вкладке изменится прогресс.

Оффбординг можно запустить одним действием из профиля, в том числе во время онбординга. Чек-лист собирает активные лицензии, роли и отслеживаемые API-ключи. Оператор выполняет действие у поставщика и вносит подтверждение, например номер заявки. Последнее подтверждение закрывает процесс и открывает скачивание акта PDF. В реестре ключей хранятся только идентификаторы.

## Архитектура

| Проект | Ответственность |
| --- | --- |
| Domain | Модель контрактов, лицензий, заявок, организаций и этапов доступа. Правила нормализации доменов, расписания и переходов состояний |
| Application | Контракты аналитики, текущего пользователя и событий рабочего пространства |
| Infrastructure | Транзакционные операции EF Core, миграции и RLS, запросы Dapper, начальные данные, генерация и подписание PDF |
| Web | MVC и Razor, HTMX, сессионная авторизация, SignalR и фоновая служба радара |
| Tests | xUnit, криптографическая проверка PDF и интеграционные проверки в MS SQL Server |

- **Изоляция.** TenantId проходит из серверного списка аккаунтов в защищённую cookie. EF Core добавляет глобальные фильтры. EF Core и Dapper устанавливают `SESSION_CONTEXT('TenantId')` как read-only при открытии каждого логического подключения. SQL-политика применяет `FILTER` к текущим и историческим таблицам, `BLOCK` после вставки и обновления. Составные ключи и связи включают TenantId.
- **Права SQL.** Локальный профиль выполняет миграции и начальную загрузку с правами Windows-пользователя. Для рабочих запросов он сначала переключает SQL-сессию на `VendorRadar_LocalRuntime` без возможности `REVERT`, отключая пул таких подключений. При развёртывании рабочий SQL-логин получает роль `VendorRadar_Runtime`, а привилегированный логин используется отдельно для миграций и администрирования. Конечные пользователи входят только через веб-приложение. Выбор TenantId доверен приложению.
- **Аудит.** `Contracts` и `AccessGrants` используют `SYSTEM_VERSIONING = ON`. Интерфейс читает историю через `FOR SYSTEM_TIME ALL` и `LAG`, показывая значимые изменения и исполнителя. Подтверждения доступа и решения о закупках сохраняются отдельно. База использует время UTC для версий и журналов, календарь рассчитывается в локальном часовом поясе процесса.
- **Финансы.** Сумма за цикл делится на 1, 3 или 12. `ROW_NUMBER` выбирает актуальный курс к USD, `SUM OVER` вычисляет накопленные расходы, ARR равен MRR × 12. Расходы отнесены к отделу договора. Курсы EUR и GBP вводит FinOps. Позиции без курса помечаются отдельно.
- **Лицензии.** Оконные функции считают назначенные и простаивающие места. Простой начинается через 30 дней после последней активности или даты выдачи. Отметку активности обновляет IT Security Admin. Свободные места считаются отдельно, API-ключи в лимит лицензий не входят.
- **Радар.** Рабочий процесс проверяет организации каждые пять минут, фиксирует события по ключу «контракт, вид события, дата» и уведомляет только SignalR-группу соответствующей организации. Из договора берётся дата оплаты и период уведомления. Календарь поддерживает 30, 60 и 90 дней. Отключённое автопродление исключает будущие повторы.
- **Закупки.** Запрос проходит руководителя своего отдела и FinOps. Сравнение с активными контрактами использует нормализованный домен, название и категорию. При совпадении или отклонении решение требует комментария.
- **PDF.** QuestPDF формирует акт и финансовую сводку. PDFsharp добавляет CMS-подпись X.509 в акт закрытия. Локальный профиль использует самоподписанный сертификат текущего процесса. Для проверки доверия и цепочки сертификатов при развёртывании укажите сертификат организации. [Лицензирование QuestPDF](https://www.questpdf.com/license/guide.html).

## Проверки

Обычный `dotnet test VendorRadar.sln` выполняет тесты правил и PDF. Чтобы дополнительно проверить RLS и Dapper на SQL Server, один раз запустите приложение для создания схемы и демоданных, затем выполните:

```powershell
$env:VENDORRADAR_SQL_TESTS = '1'
dotnet test VendorRadar.sln
Remove-Item Env:VENDORRADAR_SQL_TESTS
```

Интеграционные тесты отключают фильтры EF для проверки самой SQL-политики, проверяют temporal history, блокировку записи другой компании и неизменяемость TenantId внутри подключения. Проверка PDF восстанавливает подписанный диапазон байтов и валидирует CMS-подпись.

## Развёртывание с рабочими аккаунтами

1. Примените EF-миграции под отдельной учётной записью SQL Server. Для локального сценария подходит команда ниже. В целевой среде передайте строку подключения администратора из штатного хранилища секретов.
2. Создайте SQL-логин приложения и сопоставленного пользователя базы. Добавьте его в `VendorRadar_Runtime`. Для создания организаций и отделов используйте административное подключение к базе. Перед записью выполните `sys.sp_set_session_context` с TenantId типа `uniqueidentifier`. Значение `Organizations.Id` совпадает с `TenantId`.
3. Задайте `ConnectionStrings__VendorRadar`, хост HTTPS через `AllowedHosts`, `Pdf__CertificatePath`, `Pdf__CertificatePassword` и подходящий `Pdf__License`. Для нескольких экземпляров настройте общее защищённое хранилище ключей ASP.NET Core Data Protection и серверную доставку SignalR. Конфигурация поставки рассчитана на один экземпляр.
4. Настройте `Accounts__<account>__TenantId`, `Accounts__<account>__Name`, `Accounts__<account>__Role` и `Accounts__<account>__PasswordHash`. Допустимые роли: `Finance`, `Security`, `Lead`. Для `Lead` добавьте `Accounts__<account>__DepartmentId`. Вход в один клик работает только из loopback в Development. Данные аккаунтов и сертификаты храните в секретах среды.
5. Получите хеш пароля локально. Команда принимает пароль без отображения в терминале и выводит хеш ASP.NET Core Identity.

```powershell
dotnet run --project src/VendorRadar.Web --no-launch-profile -- --hash-password
dotnet tool install dotnet-ef --tool-path .artifacts/tools --version 10.0.14
.artifacts/tools/dotnet-ef migrations script --project src/VendorRadar.Infrastructure --idempotent
```

На стенде действия в сторонних SaaS подтверждаются вручную. Автоматическое управление доступами у поставщиков потребует интеграций SCIM или API и учётных данных этих поставщиков.
